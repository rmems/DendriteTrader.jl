Execution Engine

DendriteTrader.ExecutionEngine — Type
ExecutionEngine

Stateful execution engine with confidence gating and position management.

Fields

  • confidence_threshold: minimum SNN confidence to execute (default 0.85)
  • max_position_size: optional absolute cap on order units (default Inf, no absolute cap). Must be positive; NaN, 0 and negative values throw ArgumentError. Kelly-sized units above the cap are rejected (max_position_reject, reason prefix exceeds_max_position:), not shrunk to the cap.
  • max_position_fraction: relative cap on the projected per-ticker position as a fraction of the account_balance passed to execute_signal! (default 1.0). An order is rejected when abs(current_units ± units) * price > max_position_fraction * account_balance (max_position_reject, reason prefix exceeds_max_position_fraction:). Must be finite and positive. Orders that only reduce the existing position in that ticker (opposite side, size at most the position) are exempt, because both the price and the balance can drift after entry and a cap must not trap a position (compare #111 for max_portfolio_exposure). A sell larger than a long position is a flip and is checked. The cap is per ticker; max_portfolio_exposure bounds the portfolio. See DEFAULT_MAX_POSITION_FRACTION for why the default never binds on Kelly-sized entries. When both caps are set, both apply.
  • max_portfolio_exposure: cap on total gross notional exposure in price units across all tickers (default Inf, unlimited). Positions are valued at the last execution price seen for each ticker; a signal that only reduces an existing position is never rejected by this cap.
  • payoff_ratio: odds-style average win/loss ratio for Kelly sizing (default 1.5)
  • positions: current open positions (ticker → quantity)
  • last_prices: last execution price per ticker, for exposure valuation
  • log_file: optional path to a JSON-lines event log
  • log_io: open file handle for the event log (if configured)
  • log_lock: lock serializing log_io writes
source
DendriteTrader.DEFAULT_MAX_POSITION_FRACTION — Constant
DEFAULT_MAX_POSITION_FRACTION = 1.0

Default relative position cap for ExecutionEngine and BacktestConfig: the projected position in one ticker after an order, valued at the order price (abs(current_units ± units) * price), may not exceed this fraction of the account_balance passed to execute_signal!. run_backtest passes its cash balance, which does not fall when a position opens (only commissions and realized PnL change it). The cap is per ticker. It does not bound the sum across tickers (use max_portfolio_exposure for that), so it is not a portfolio-wide leverage limit.

Why 1.0: execute_signal! sizes with size_position at its default kelly_scalar = 0.5, whose Kelly fraction is 0.5 * (p*b - q)/b, capped to [0, 1]. Because (p*b - q)/b <= 1 for every p in [0, 1] and b > 0, a Kelly-sized entry commits at most 0.5 of the balance (reached only at confidence 1.0). A default of 1.0 therefore never rejects a single Kelly-sized entry from flat and leaves a 2x margin, so floating-point rounding at the boundary cannot flip that decision. It does bind when repeated same-side entries accumulate: a third Kelly buy at confidence 0.92 (about 0.433 each) projects about 1.3 of the balance and is rejected. It is a backstop, not a sizing policy.

The [0, 0.20] output cap of kelly_fraction does not apply here: execute_signal! does not call kelly_fraction, so Kelly-sized entries can commit up to 0.5 of the balance (about 0.458 at confidence 0.95 with payoff_ratio = 1.5). A relative cap at or below 0.5, such as 0.25, would reject ordinary high-confidence entries.

DendriteTrader.execute_signal! — Function
execute_signal!(engine, signal, account_balance; observed_ns=nothing,
                position_units_override=nothing) -> ExecutionDecision

Process one signal: gate by confidence, size via Kelly, update positions.

observed_ns supplies a deterministic observation timestamp for replay. Live callers omit it to use the wall clock. position_units_override is reserved for simulators that must apply an explicit filled quantity, such as a full-position close; the decision event and position ledger both use the overridden quantity.

Rejections

Every rejection increments rejected_signals, records a SignalEvent, and returns an ExecutionDecision with executed = false and an explicit reason:

  • gate_reject: confidence below the engine threshold.
  • neutral_reject: Neutral side.
  • sizing_reject (reason prefix invalid_sizing_input:): size_position rejected its inputs, e.g. signal.price <= 0, account_balance <= 0, a non-finite value, or confidence outside [0, 1].
  • max_position_reject: a position cap was hit. The reason names the cap:
    • prefix exceeds_max_position: when Kelly-sized units exceed the absolute engine.max_position_size (default Inf, no absolute cap);
    • prefix exceeds_max_position_fraction: when the projected position in the ticker, abs(current_units ± units) * signal.price, exceeds engine.max_position_fraction * account_balance (default fraction 1.0). Orders that only reduce the existing position in the ticker are exempt from this relative cap; a flip past flat is checked.
    When both caps are set, both apply and the absolute cap is checked first. Nothing is shrunk to a cap: the whole order is rejected and no position changes.
  • zero_reject: the Kelly fraction is zero (no edge), so the sized position is zero.
  • portfolio_reject: the projected gross exposure would exceed max_portfolio_exposure.

An invalid position_units_override (non-finite, negative, above max_position_size, or, for an order that does not only reduce the position, with notional above max_position_fraction * account_balance for the projected position) is a caller error and throws ArgumentError whose message carries the same cap reason. When an override is supplied and account_balance is finite but <= 0, Kelly sizing is skipped (the override quantity does not depend on it) so an existing position can still be closed; price and confidence are still validated (as in size_position) and the reported kelly_fraction is 0.0. The carve-out covers a finite balance <= 0 only: a non-finite balance (NaN, ±Inf) means the accounting is already broken and is rejected as sizing_reject even with an override.

A valid input that yields zero Kelly units, such as no edge or kelly_scalar = 0, is a real sizing decision and is reported as zero_reject, not as sizing_reject.

Behavior change: earlier versions silently capped Kelly-sized units with min(units, max_position_size) and executed the reduced size, and treated account_balance <= 0 or price <= 0 as a zero_reject with no specific reason. The default cap is now relative (max_position_fraction = 1.0) instead of a fixed max_position_size = 10.0 units, which rejected ordinary Kelly-sized entries at a 10_000 balance and prices below about 1_000 × k.

DendriteTrader.start! — Function
start!(engine; zmq_endpoint, zmq_topic, account_balance, on_decision,
       timeout_s, reconnect_interval_s, max_reconnect_attempts)

Start the ZMQ SUB listener loop (requires ZMQ.jl).

Subscribes to zmq_endpoint and processes incoming JSON trade signals through the execution engine, calling on_decision for each result.

Arguments

  • engine: ExecutionEngine instance
  • zmq_endpoint: ZMQ endpoint (e.g. "tcp://localhost:5555" or "ipc:///tmp/signals.ipc")
  • zmq_topic: ZMQ topic filter prefix (default "" = all messages)
  • account_balance: account size for Kelly sizing
  • on_decision: callback (ExecutionDecision) -> Nothing
  • timeout_s: total seconds to run before auto-stopping (nothing = run forever)
  • reconnect_interval_s: seconds to wait between reconnection attempts (default 5.0)
  • max_reconnect_attempts: max reconnection attempts; 0 = infinite (default 0)

Shutdown

Call stop!(engine) from another task to gracefully stop the listener. The loop checks engine.should_stop periodically.

Example

engine = ExecutionEngine(confidence_threshold=Float32(0.85))

# Run in background task
t = @async start!(
    engine,
    zmq_endpoint="tcp://localhost:5555",
    zmq_topic="trade.signal",
    on_decision = decision -> println("Decision: $(decision.executed)"),
)

# Stop after 60 seconds
sleep(60)
stop!(engine)

DendriteTrader.load_config — Function
load_config(path) -> ExecutionEngine

Create an ExecutionEngine from a flat TOML (.toml) or YAML (.yaml/.yml) file. The supported keys are confidence_threshold, max_position_size, max_position_fraction, max_portfolio_exposure, payoff_ratio, log_file, and truncate; omitted keys use the constructor defaults. Numeric configuration values are converted to the engine's concrete numeric types, and YAML null is accepted for log_file. All numeric values must be finite. Omit max_position_size for no absolute unit cap and max_portfolio_exposure for the unlimited exposure default (both Inf); when set in a file each must be a positive finite cap. confidence_threshold must be in [0, 1], and max_position_size, max_position_fraction, max_portfolio_exposure, and payoff_ratio must be positive. Relative log_file paths are resolved relative to the configuration file.

An unsupported extension, a non-mapping YAML document, an unknown key, or a value of the wrong type raises ArgumentError. Syntax errors from the selected parser are propagated.

File configuration

load_config(path) creates an ExecutionEngine from a flat TOML or YAML file. Only the constructor keys below are accepted; omitted keys retain their defaults.

KeyTypeDefault
confidence_thresholdfinite number in [0, 1]0.85
max_position_sizepositive finite number (absolute unit cap)none (Inf)
max_position_fractionpositive finite number (projected per-ticker position notional ÷ the account_balance passed to execute_signal!; run_backtest passes its cash balance, which does not fall when a position opens (only commissions and realized PnL change it))1.0
max_portfolio_exposurepositive finite number (gross notional, all tickers)none (Inf)
payoff_ratiopositive finite number1.5
log_filestring or YAML nullno event log
truncatebooleanfalse
# engine.toml
confidence_threshold = 0.9
max_position_size = 25.0
payoff_ratio = 1.75
log_file = "events.jsonl"
truncate = true
# engine.yaml
confidence_threshold: 0.9
max_position_size: 25.0
payoff_ratio: 1.75
log_file: events.jsonl
truncate: true
engine = load_config("engine.toml")

Unknown keys, non-mapping documents, and values with the wrong type throw an ArgumentError; malformed TOML or YAML propagates its parser error. Relative log_file paths are resolved from the directory containing the configuration file.
