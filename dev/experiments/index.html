SNN Market-Microstructure Experiments

DendriteTrader is an experimental market-microstructure and paper-execution laboratory. It evaluates whether spike-based models produce useful, calibrated forecasts from causally available market events after declared latency, fill, fee, and risk assumptions.

It is not a production HFT runtime, an authenticated exchange client, or a source of financial advice. Venue-critical execution remains outside this Julia package.

Experiment boundary

The research pipeline is intentionally decomposed:

market events -> causal features -> spike encoder -> forecast model
              -> calibration -> policy -> paper simulator -> evidence artifacts

DendriteTrader owns finance-specific schemas, features, labels, policies, paper execution, and experiment orchestration. Reusable neuron dynamics, plasticity, and generic SNN training belong in dedicated neuromorphic packages and connect through adapters. Deterministic low-latency IPC and real venue execution belong in separate services.

Scientific requirements

Every reported experiment must preserve:

  • a chronological train/validation/test split with an embargo at least as long as the maximum feature or forecast horizon;
  • training-only normalization and calibration;
  • explicit event-time and physical-time horizons;
  • non-SNN baselines evaluated on the same decisions and market events;
  • declared fees, latency, fill, and queue assumptions;
  • per-session metrics and aggregate uncertainty, not only one headline total;
  • configuration, data hashes, code revision, seeds, environment, and model identity;
  • negative and null findings;
  • no credentials, wallet material, or live order submission.

Evidence families

Experiments report four complementary groups of measurements:

  1. Predictive: MCC, macro F1, balanced accuracy, and per-class precision/recall.
  2. Calibration: Brier score, expected calibration error, and reliability bins.
  3. Paper execution: net PnL, implementation shortfall, turnover, fill rate, inventory exposure, drawdown, and completed-transaction correctness.
  4. Systems/SNN: encoding and inference latency percentiles, throughput, spike density, silent or saturated channels, memory, and a clearly labeled energy proxy or hardware measurement.

Classification performance alone is not evidence of an actionable strategy.

Initial campaign

The first campaign compares a queue-imbalance rule, a linear classifier, a uniform-time-constant LIF network, and a mixed-memory LIF network. All models consume the same causal book-derived features and are evaluated at the same decision times.

The campaign starts with deterministic synthetic fixtures in CI. Real-data runs use separately acquired data with a session manifest recording license, venue, instrument, timestamp semantics, depth, parser revision, raw hashes, sequence-gap policy, and known limitations. Raw licensed or large market data is not committed.

Zero-cost and zero-latency scenarios are diagnostics, not realistic claims. L2 data may support an explicitly approximate queue model; queue-accurate claims require suitable order-level data.

Canonical replay input

The replay kernel accepts newline-delimited JSON containing book_delta and trade_print events. Prices and sizes use integer ticks and units; floating-point prices are deliberately excluded from this boundary. Every record identifies one venue and instrument and carries positive exchange/receive nanosecond timestamps plus a positive sequence number.

{"type":"book_delta","venue":"SIM","instrument":"XYZ","exchange_ts_ns":1000,"receive_ts_ns":1010,"sequence":1,"side":"BID","price_ticks":100,"size_delta":10}
{"type":"trade_print","venue":"SIM","instrument":"XYZ","exchange_ts_ns":1001,"receive_ts_ns":1011,"sequence":2,"aggressor_side":"BUY","price_ticks":102,"size":3}
session = load_session_jsonl("session.jsonl")
book = OrderBookState(session.venue, session.instrument)
snapshots = replay!(book, session)

Replay is fail-closed by default: sequences must strictly increase without gaps, exchange and receive timestamps cannot move backward, depth cannot become negative, and an update cannot cross the book. Batch replay is transactional: any invalid event leaves the destination book unchanged. A feed known to omit events or use non-contiguous sequence values may use ReplayPolicy(allow_sequence_gaps=true) explicitly; that assumption remains part of the ReplaySession. Trade prints advance event time and sequence but do not invent unobserved changes to L2 depth.

Causal dataset layer

microstructure_features emits one row only after both sides of the book exist. Each row contains the integer spread, mid-price, size-weighted microprice, top-level imbalance, and signed top-of-book order flow. The calculation reads the current and immediately preceding complete snapshots only; it rejects mixed venues, mixed instruments, and non-monotonic event streams. Sequence gaps are rejected by default because signed order flow requires adjacent exchange events. Set allow_sequence_gaps=true only when the input is intentionally an observed-event stream.

RollingZScore is fit explicitly on a supplied training FeatureFrame and records the final training sequence. transform! never updates those fitted parameters, so validation and test observations cannot change the training normalization evidence. normalization_parameters returns the feature order, means, scales, and fitting boundary in JSON-serializable form.

label_event_horizon compares an anchor with the snapshot at the exact future event offset in the original stream. It omits incomplete anchors or exact targets rather than compressing time, and each MovementTarget records both sequences for unambiguous alignment. Sequence gaps are rejected by default. Labels never cross the supplied session boundary. walk_forward_splits constructs expanding training windows with disjoint validation/test windows and explicit embargo gaps; it rejects an embargo shorter than the declared maximum feature or label horizon.

Tiny CPU baseline

This no-network, no-GPU example fits a stationary baseline on chronological training data, then returns a normalized three-class forecast:

using DendriteTrader

rows = FeatureFrame([FeatureRow(10, 1, 1, 100, 100, -0.2, 0),
                     FeatureRow(20, 2, 1, 101, 101, 0.3, 1)])
model = fit!(StationaryModel(), rows, [MovementTarget(1, 2, 1, Up)])
forecast = only(predict!(model, FeatureFrame([rows[1]]), ForecastHorizon(1)))

Forecast.probabilities use (Down, Flat, Up) order. They are class probabilities, not calibrated win probabilities, and must not be passed directly to Kelly sizing.

Latency-aware paper simulation

simulate!(portfolio, session, decide; config) replays one ReplaySession as a deterministic event-driven paper simulation. It never submits orders, reads credentials, or touches a network, and its fills are hypothetical inferences from L2 data, not observed executions.

Four clocks are kept separate for every order: the time the information used by the decision became observable (info_available_ts_ns, from the feed-delay model — ReceiveTimestampFeed or FixedFeedDelay), the decision time, the activation time (decision + FixedLatency.order_entry_ns), and each fill time (never earlier than activation). Cancels take effect after cancel_ns, and fills become visible to the decision function only after report_ns.

Zero latency is allowed only as a labelled diagnostic. If any of order_entry_ns, cancel_ns or report_ns is zero, assumptions["latency"]["diagnostic_zero_latency"] is true and assumptions["latency"]["zero_latency_components"] names the zero components; is_zero_latency_diagnostic(result) reads the flag. All three trigger it because each removes a delay that favours the strategy: zero order entry fills at the decision instant, zero cancel withdraws orders before any venue event can reach them, and zero report shows the decision its own fills immediately. The flag is part of result_hash, and such a run must not be reported as evidence. Feed delay is recorded separately under assumptions["feed"] and does not set this flag.

decide(ctx::DecisionContext) sees only: the decision time; the newest observable event (event, its info_sequence and info_exchange_ts_ns); a private copy of the observed book snapshot; the causal microstructure_features row for it; reported inventory and cash; and reported working orders. Mutating ctx.snapshot cannot change later features or fills.

The hard guarantee against label leakage is structural: DecisionContext has no label, target, or outcome fields, and reading any other property throws. In addition, a best-effort runtime scan refuses a decision closure or callable struct that captures MovementTarget values within 4 nested levels (the closure's captured variable is level 1). The scan does not see globals or deeper nesting; it is a guard against accidental capture, not a sandbox. ForecastPolicy is a minimal example that wires a fitted Task 4 forecast model into long/flat IOC orders; it is not a strategy claim.

L2QueueApproximation is an explicitly approximate fill model (compare the hftbacktest order-fill documentation). Its rules are copied into SimulationResult.assumptions: marketable orders sweep displayed liquidity within the limit; consumed displayed liquidity is not reused; resting orders join the back of their level (or a seeded position with queue_position = :random, never ahead of an earlier simulated order at that level); prints at the order's price advance the queue, and a displayed-size decrease advances it only when the level becomes smaller than the venue size still ahead; simulated orders at one level are first-in, first-out by join order; a print walks the hit side from the best price to the print price, filling better-priced queues first; quote-throughs fill better-priced resting orders first; orders whose activation falls after the last replayed event expire unfilled; and there is no market impact or matching-engine guarantee.

FeeSchedule applies one integer fee per fill (positive commission, negative rebate, parts-per-million of notional, commissions rounded up). Declared taker slippage is in the fill price and reported separately; neither is charged again.

PaperPortfolio is an integer evaluation state, not an authoritative ledger. In the default :long_flat mode it follows the metabolic-ledger accounting contract exactly (single instrument, inventory never negative, sells beyond inventory rejected as unsupported_short, truncating cost allocation, full close takes remaining cost). :signed mode is a Julia-only research extension; its results are labelled outside the parity subset and parity_document refuses to export them. Marks use only the venue mid at or before each step (rounded half a tick against the position); a one-sided book yields a :stale mark and no prior mid yields :missing (no equity is invented). reconciliation_errors independently re-derives cash, inventory, fees, unrealized PnL, equity and drawdown at every step.

The vendored metabolic-ledger.parity.v1 fixtures (with PROVENANCE.json recording the source commit and SHA-256 of each file) are replayed by run_parity_fixture, and parity_document emits a long/flat simulation in the same schema for the Rust harness. decision_records and fill_records emit normalized JSON-ready records for a later trajectory export; that export is not implemented here.

DendriteTrader.Simulation.PaperOrder — Type
PaperOrder

Simulator-owned lifecycle of one accepted (or rejected) OrderIntent.

Four clocks are kept separate:

  • info_available_ts_ns: when the newest event the decision used became observable under the configured feed-delay model (info_sequence identifies that event);
  • decision_ts_ns: when the decision function ran (equal to the information time; compute latency is part of FixedLatency.order_entry_ns);
  • activation_ts_ns: decision_ts_ns + order_entry_ns, the earliest venue time at which the order can interact with the book;
  • each Fill.exchange_ts_ns, which is never earlier than activation_ts_ns.

status is one of :pending, :active, :filled, :cancelled, :rejected, :expired (still working when the session ended). queue_ahead_lots is the estimated venue (non-simulated) size still ahead of the order at its level; earlier-joined simulated orders at the same level are ahead of it too and are accounted for separately, in FIFO join order (join_seq), at each print. initial_queue_ahead_lots is the total (venue + simulated) size ahead when it joined. All of these are L2 approximations, not observed queue positions.

DendriteTrader.Simulation.FixedLatency — Type
FixedLatency(order_entry_ns; cancel_ns=order_entry_ns, report_ns=order_entry_ns)

Deterministic decision-to-venue latency. An order decided at t becomes active at t + order_entry_ns and cannot interact with any venue book state before then (venue events stamped exactly at the activation time are applied first). A cancel decided at t takes effect at t + cancel_ns; the order may fill in between. A fill or terminal order state at venue time u becomes visible to the decision function at u + report_ns. Zero latency is allowed as an explicit diagnostic, not a realistic claim: any zero component marks the run as a zero-latency diagnostic (see zero_latency_components).

DendriteTrader.Simulation.L2QueueApproximation — Type
L2QueueApproximation(; queue_position=:back, taker_slippage_ticks=0, seed=0)

Declared, approximate fill model for L2 (price-level aggregated) replay data. Price-level data does not reveal queue position, so every passive fill below is an inference, not an observed fill (compare the hftbacktest order-fill documentation).

Assumptions, all recorded in SimulationResult.assumptions:

  1. Activation: an order can interact only with venue state at or after decision_ts + order_entry_ns; venue events stamped at the activation instant are applied first. It never trades against a print that occurred before activation.
  2. Taking: a marketable order sweeps displayed opposite levels inside its limit at each level's price (plus taker_slippage_ticks adverse ticks), as taker. Whether an order crosses is judged on its raw limit: a post-only order whose limit is at or through displayed opposite size is rejected (post_only_would_take) whatever the slippage, and an order whose remaining size still crosses after the sweep (because slippage put those levels outside the limit) is terminated (cross_unfillable_after_slippage). A crossed order never rests.
  3. Depletion: displayed liquidity the simulator consumed stays unavailable at that price until the replayed level is fully removed; new displayed size adds back.
  4. Joining: a resting order joins the back of its price level (queue_position = :back), or a seeded uniform position in [0, displayed] when queue_position = :random (less conservative, labelled as such).
  5. Queue advance (risk-averse): only trade prints at the order's price advance the queue; displayed-size decreases advance it only when the level becomes smaller than the remaining venue queue ahead. Simulated orders at one level form a FIFO queue in join order: an order's queue ahead is its venue-ahead estimate plus the remaining size of simulated orders that joined earlier, and venue cancels never reduce the simulated part. Print volume that filled simulated orders at their price is treated as venue size that would still be resting (no market impact), both when later orders join and when capping on displayed-size decreases. A print fills only the size left after the queue.
  6. Price priority: a print walks the hit side from the best price down to the print price. At each level it consumes that level's whole estimated queue (venue lots and simulated orders in FIFO order, including venue lots our orders absorbed earlier) before reaching worse levels. A print strictly through a resting limit can therefore fill it only after better-priced and earlier-queued size is used up.
  7. Quote-through: opposite displayed liquidity appearing strictly through a resting limit fills it as maker at the limit price, up to that displayed size, better-priced resting orders first, then join order. A locked quote (equal price) does not fill.
  8. No market impact: hypothetical fills do not alter the replayed book beyond the depletion bookkeeping above. No matching-engine guarantee is implied.

DendriteTrader.Simulation.PaperPortfolio — Type
PaperPortfolio(instrument, initial_cash_subunits; scale=ParityScale(), mode=:long_flat)

Single-instrument integer evaluation state for the paper simulator. It is a reference/evaluation state for experiments, not an authoritative or persistent ledger; persistent accounting belongs to metabolic-ledger.

mode = :long_flat is the declared cross-language parity subset (inventory never negative; a sell beyond inventory is :unsupported_short, never clamped). mode = :signed is a Julia-only research extension that allows short inventory and position flips; results in that mode are outside the parity subset and are labelled so.

Accounting (identical to the metabolic-ledger accounting contract in the long/flat subset):

  • Buy cash change -(notional + fee); sell cash change +(notional - fee).
  • fee > 0 is a commission, fee < 0 a rebate; each fill's fee is applied once.
  • total_cost_subunits holds the signed position cost; buy fees enter the basis.
  • A reduction allocates trunc(total_cost * qty / |inventory|) toward zero, and a full close allocates the remaining cost. Realized PnL is cash_flow - allocated.
  • Invariant: cash + total_cost == initial_cash + realized_pnl.

simulation_runs counts simulate! runs committed to this portfolio. simulate! only accepts a fresh portfolio (zero runs, empty audit); the r<run>- prefix on order and fill ids is kept as defence in depth against id collisions.

DendriteTrader.Simulation.simulate! — Function
simulate!(portfolio, session, decide; config) -> SimulationResult

Run a deterministic paper simulation of session and commit the resulting state to portfolio only if the whole run succeeds (any error leaves portfolio unchanged).

decide(ctx::DecisionContext) is called once per observed market event, at the time the event becomes observable under config.feed, and returns nothing, an OrderIntent/CancelIntent, or a vector of them. Orders are risk-checked at the decision time (a rejection mutates nothing but the audit trail) and activated at decision_ts + config.latency.order_entry_ns.

Requires a fresh portfolio (no committed simulation run and an empty audit trail), portfolio.instrument == session.instrument, qty_scale == 1 (so every partial fill notional is exact) and initial cash within config.limits. Reusing a portfolio is refused because SimulationResult reconciliation and parity_document describe one run from a flat, fee-free, PnL-free start; create a new PaperPortfolio per run.

DendriteTrader.Simulation.ForecastPolicy — Type
ForecastPolicy(model, horizon; threshold, order_lots, max_inventory_lots)

Minimal long/flat example policy built on a fitted Task 4 AbstractForecastModel. At each observed complete book it predicts one Forecast from the causal feature row only. If P(Up) >= threshold and the reported inventory has room it sends an IOC buy limited at the observed best ask; if P(Down) >= threshold and inventory is long it sends an IOC sell of the reported inventory limited at the observed best bid. It does nothing while it has an unreported working order. It is a wiring example, not a strategy claim.

DendriteTrader.Simulation.zero_latency_components — Function
zero_latency_components(latency) -> Vector{String}

Names of the FixedLatency components that are zero, in the order order_entry_ns, cancel_ns, report_ns. Each one removes a delay a real participant always pays: zero order entry fills at the decision instant, zero cancel lets a decision withdraw an order before any venue event can reach it, and zero report reveals its own fills (and the book state they imply) to the next decision with no lag. All three bias results in the strategy's favour, so any of them makes a run a diagnostic.
